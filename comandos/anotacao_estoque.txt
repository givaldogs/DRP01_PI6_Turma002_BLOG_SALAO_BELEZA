Minha recomendação é adotar exatamente essa estrutura: cada funcionário acessa apenas a filial em que trabalha, enquanto o administrador autorizado pode consultar e gerenciar todas as filiais. Esse é um modelo de controle de acesso bastante adequado para um sistema de estoque com matriz e filiais.

Vou explicar como eu projetaria isso para o seu PI6.

## 1. Como funcionaria o acesso ao sistema

Administrador geral

Todas as filiais

Cadastra filiais e produtos, consulta os estoques, gerencia usuários e acompanha relatórios consolidados.

Gerente de filial

Consulta o estoque da sua unidade, registra entradas e saídas e acompanha produtos com estoque baixo.

Funcionário

Consulta produtos e registra apenas as operações autorizadas para sua filial.

## 2. Por que considero esse o modelo mais adequado?

- Segurança: um funcionário de uma unidade não deve conseguir alterar o estoque de outra.
- Organização: cada filial tem seu próprio saldo de produtos.
- Rastreabilidade: cada movimentação registra o usuário responsável, a data e o motivo.
- Crescimento: você começa com uma unidade e pode cadastrar outras sem reconstruir o sistema.

Um detalhe importante: não basta esconder as outras filiais na tela. O Django também precisa validar as permissões no servidor, inclusive quando alguém tenta acessar uma URL diretamente.

## 3. Como vamos implementar no Django

## Etapa 2 — Criar os três primeiros modelos

No VS Code, substitua o conteúdo atual de `djangoapp/estoque/models.py` pelo código abaixo:

```
from django.db import modelsclass Empresa(models.Model):    nome = models.CharField(max_length=150)    cnpj = models.CharField(max_length=18, unique=True, blank=True, null=True)    ativa = models.BooleanField(default=True)    def __str__(self):        return self.nomeclass Filial(models.Model):    empresa = models.ForeignKey(        Empresa,        on_delete=models.PROTECT,        related_name='filiais'    )    nome = models.CharField(max_length=100)    codigo = models.CharField(max_length=20)    endereco = models.CharField(max_length=200, blank=True)    ativa = models.BooleanField(default=True)    class Meta:        unique_together = ('empresa', 'codigo')    def __str__(self):        return f'{self.nome} - {self.empresa.nome}'class Categoria(models.Model):    nome = models.CharField(max_length=100, unique=True)    descricao = models.TextField(blank=True)    ativa = models.BooleanField(default=True)    def __str__(self):        return self.nome
```

Salve o arquivo com `Ctrl + S`.

## Entendendo o código

### 1. `Empresa`

Representa a empresa proprietária do salão.

- `nome`: nome da empresa.
- `cnpj`: identificação da empresa, opcional neste primeiro momento.
- `ativa`: permite marcar a empresa como ativa ou inativa.

### 2. `Filial`

Representa a matriz ou uma unidade da empresa.

O trecho:

```
empresa = models.ForeignKey(    Empresa,    on_delete=models.PROTECT,    related_name='filiais')
```

estabelece uma relação entre a filial e a empresa.

- `ForeignKey`: relaciona um registro com outro.
- `Empresa`: indica a qual empresa a filial pertence.
- `on_delete=models.PROTECT`: impede excluir uma empresa enquanto houver filiais vinculadas.
- `related_name='filiais'`: permite consultar as filiais de uma empresa por meio de `empresa.filiais.all()`.

O `unique_together` evita que a mesma empresa tenha duas filiais com o mesmo código.

### 3. `Categoria`

Organiza os produtos, por exemplo, em categorias como esmaltes, shampoos, tinturas e materiais descartáveis.

O campo `unique=True` impede cadastrar duas categorias com exatamente o mesmo nome.

class UnidadeMedida(models.Model):
    nome = models.CharField(max_length=50, unique=True)
    sigla = models.CharField(max_length=10, unique=True)
    ativa = models.BooleanField(default=True)

    def __str__(self):
        return f'{self.nome} ({self.sigla})'

O que cada campo faz?
- nome: nome da unidade, como Frasco, Pacote ou Quilograma.
- sigla: abreviação, como FR, PCT ou KG.
- ativa: indica se a unidade está disponível para novos cadastros.
- __str__: define como a unidade será apresentada no Django Admin.
